# Delivery Roadmap

1. **Phase 1 — Contract foundation:** versioned JSON schemas, TypeScript reference SDK, cross-domain examples and contract CI. **Implemented in pre-alpha.**
2. **Phase 2 — Open Control Runtime:** SQLite-backed single-node runtime, persistent work graph, execution lifecycle, transactional checkpoints/recovery and JSON-first `q1x` CLI. **Implemented in pre-alpha.**
3. **Phase 3 — Capability discovery and live registry:** manifest-driven command/path/environment/HTTP probes, persistent registry and discovery CLI. **Implemented in pre-alpha.**
4. **Phase 4 — Provider-neutral model transport and local inference:** secure endpoint registry, pluggable protocol transports, local-first compatible APIs and CLI invocation. **Implemented in pre-alpha.**
5. **Phase 5 — MCP, A2A and CLI/TUI adapters:** executable endpoint registry, official MCP transports, A2A Agent Card/JSON-RPC support and direct no-shell CLI execution. **Implemented in pre-alpha.**
6. **Phase 6A — Browser/web control:** managed real-browser sessions, Chromium-family CDP attachment, normalized web actions, bounded files/captures and browser CLI. **Implemented in pre-alpha.**
7. **Phase 6B — Desktop/application control:** OS-neutral desktop contracts, pluggable backends, direct no-shell stdio bridge execution, application policy, capability discovery and desktop CLI. **Implemented in pre-alpha.**
8. **Phase 7 — Dynamic team formation and adaptive programme supervision:** deterministic capability routing, durable logical teams and assignments, bounded supervision cycles, cancellation/replacement, budgets, approvals, checkpoints and validated replanning. **Implemented in pre-alpha.**
9. **Phase 8 — Cross-platform packaging and Docker deployment:** Node.js source install on macOS/Windows/Linux, non-root multi-stage OCI image, persistent state, health/readiness lifecycle, Compose hardening, explicit configuration and cross-platform installation verification. **Implemented in pre-alpha.**
10. **Phase 9 — Security, approvals, evidence, audit and recovery hardening:** single-use consequential-action approvals, immutable evidence provenance, metadata-only tamper-evident audit receipts and checkpoint-backed interrupted-work recovery. **Implemented in pre-alpha.**
11. **Phase 10 — Public alpha commissioning:** version-locked `0.1.0-alpha.1` package set, governed tarballs, SHA-256 release evidence, clean external-consumer verification, cross-platform commissioning, fail-closed GitHub prerelease workflow and optional trusted npm publication lane. **Implemented and commissioned as `v0.1.0-alpha.1` from protected `main`.**
12. **Phase 11 — Compatibility matrix and community adapter SDK:** evidence-driven tested/experimental/unsupported compatibility declarations, deterministic generated matrix documentation, separate Community Adapter SDK, conformance runner, explicit runtime bridge and local reference adapter. **Implemented on protected `main` and included in the commissioned `v0.1.0-alpha.1` GitHub public alpha.**
13. **Phase 12 — Core usability and ecosystem completion:** standalone connector catalogue/configure/test/enable/apply flows, `q1x doctor`, ready-to-use model/MCP/A2A/CLI/browser profiles, shipped first-party macOS/Windows/Linux desktop bridges, cross-platform no-custom-code product acceptance, evidence-backed compatibility promotion and eight-package `0.1.0-alpha.2` release governance. **Implemented on protected `main`; exact-head and post-merge commissioning gates passed.**
14. **Phase 13 — Product hardening and beta readiness:** durable state/version integrity, verified backup/restore, crash-consistent external-operation journalling, bounded limits/retry semantics, deterministic resilience/stress/soak evidence, reproducible packages with SPDX SBOM, evidence-tiered compatibility and complete operating manuals. **Implemented as the `0.2.0-beta.1` beta-ready source candidate; immutable beta commissioning remains a separate authority.**
15. **Phase 14 — Stable release readiness:** frozen public/package compatibility surfaces, explicit state migration and upgrade evidence, bounded restart/soak evidence, deterministic dependency/licence inventory, stable versioning/deprecation/support policy and governed `1.0.0-rc.1` release identity. **Implemented and post-merge validated on protected `main` as the `1.0.0-rc.1` stable-readiness candidate; `1.0.0` is not commissioned and remains a separate immutable authority.**

Phase 12 remains the completed baseline usability gate, and Phase 13 hardens that standalone baseline into the uncommissioned `0.2.0-beta.1` beta-ready candidate without introducing a mandatory private control plane. Phase 14 prepares `1.0.0-rc.1` as the stable-readiness candidate, but `1.0.0` is not commissioned. The historical `v0.1.0-alpha.1` remains immutable and `v0.1.0-alpha.2` remains the current commissioned GitHub public alpha until a later explicit release authority is exercised. npm publication is optional and independently authorised. The software remains experimental; production/general-availability and SLA claims remain out of scope.
